# Как добавлять новые блюда в общий каталог

Личные рецепты пользователь добавляет в приложении. Общий каталог FoodMatch
обновляется проверенным пакетом данных через PR. Не нужно создавать отдельное
блюдо для немецкого языка: оба перевода используют один UUID.

## Что подготовить для каждого блюда

- Название и описание на английском и немецком.
- Число порций, ингредиенты с точными количествами и единицами. Указать, относится
  вес к сырому или готовому продукту, и съедобную часть, если это существенно.
- Последовательные шаги на обоих языках; время, температура, альтернативы и
  предупреждения должны совпадать по смыслу.
- Время подготовки, приготовления и общее время с учётом ожидания. Параллельные
  операции не следует автоматически складывать.
- Кухня, категория, диетические признаки и исключения. Они хранятся стабильными
  кодами, а не немецкими подписями. Проверить аллергены по всем ингредиентам.
- Фото, источник и право использования. Для калорий — источник расчёта, порция
  и пометка приблизительной оценки; неизвестное значение не заменять нулём.

Можно прислать JSON или таблицу с этими полями. После проверки готовится пакет
для нормализованных таблиц `dishes`, секций, ингредиентов, измерений и шагов.
Существующие ингредиенты переиспользуются по ID. Новому блюду назначается один
UUID, который больше не меняется при исправлении текста или переводе.

## Порядок публикации

1. Подготовить рецепт и оба языка; проверить количества, выход, время и теги.
2. Создать отдельный пакет добавления данных в одной транзакции. Использовать
   явный список новых ID, проверку дублей и предварительный просмотр изменений.
3. После формирования исходных текстов обновить `source.en.json` и запись
   перевода с тем же ID и актуальным `sourceHash` в `de.json`.
4. Выполнить проверки из README. Они проверяют комплектность и числа, но не
   заменяют проверку рецепта человеком.
5. На тестовой базе проверить карточку, подробный рецепт, EN/DE, поиск, фильтры,
   порции и список покупок. Проверить повторный запуск пакета и откат.
6. Сохранить резервную копию основной базы, просмотреть точный diff и применить
   проверенный пакет. Не изменять пользовательские блюда, лайки и сессии.

Прямое редактирование одной строки `dishes` в Dashboard не обеспечивает
согласованность дочерних таблиц. Старые MongoDB-import команды не являются
процессом добавления новых рецептов. Универсальный импортёр новых блюд этим PR
пока не реализован; для каждого пакета нужен проверенный сценарий импорта.

При изменении исходного рецепта перевод нужно пересмотреть и пересчитать хеш.
Не переносить прежний статус проверки автоматически на новый текст.
